# Intention web: full-width responsive renderer + marketing site + sign-in deep-link

The renderer gets a browser-only layer that drops the Electron quarter-width constraint and makes every page usable from 375px to 1440px, without touching the desktop app's narrow column. A standalone marketing page at `web/index.html` reuses the app's design tokens and routes its CTAs into the web app, including a `?signin=1` deep-link that auto-opens the auth modal. Browser detection is the absence of `window.electronAPI`: an inline head script tags `<html>` with `web-mode` before any stylesheet paints, and all new rules live under `html.web-mode` in a `css/web.css` linked last. The real Supabase email-OTP sign-in is reachable from the nav and from the marketing page.

Watch for: the two feature commits (`de5dac4`, `0b6b221`) also carry a large amount of unrelated pre-existing renderer work — calendar page, Online tab, background sounds, breathing, yap sheet, task-suggest, and the FocusFlow→Intention rebrand — folded into the same commits as the web-mode change (confirmed). This is a commit-hygiene issue, not a requirement failure; the task deliverables themselves are correct and scoped. Browser sign-in is per-session only (`persistSession:false`), so a reload drops the session (confirmed, and intentional per context).

**Verdict**: APPROVED

## High-level view

The web-mode gate is clean. The inline detection script runs before stylesheets so there is no flash of the narrow layout, and because every new selector is scoped under `html.web-mode` with the stylesheet linked last, no `!important` is needed and the Electron path is provably untouched. The two task commits modified only `index.html`, `css/web.css`, and the `web/` files — `main.js`, `preload.js`, the `.ps1` helpers, `ios/`, `dist/`, and `mini.html` were not touched by this work.

Full-width works as specified: `.page` becomes a centered 1200px band, the nav aligns to the same band, and `#page-calendar` is explicitly held full-width. Desktop ≥1025px lays Timer out in two columns and Scheduler in three; tablet drops Scheduler to two; mobile ≤600px stacks nav/inputs, wraps timer controls, allows horizontal scroll on the calendar grids, and shrinks every modal — including the shared `.cw-modal` auth/calendar backdrop — to fit a 375px viewport.

Sign-in is genuinely functional, not stubbed. `supabase-config.js` carries a real project URL and anon key (`isConfigured()` is true), the nav `#nav-account` button is wired to `openModal`, and `window.openAuthModal` is exposed so the marketing `?signin=1`/`#signin` deep-link can trigger it. The deep-link only fires when the flag is present, so a plain `/index.html` visit does not pop the modal.

The marketing page is self-contained and visually consistent: it links `../css/style.css` for the tokens plus its own `marketing.css`, draws every preview as inline SVG or CSS (zero `<img>`, so no broken images), and its CTAs point at `../index.html`, the GitHub releases page, and `../index.html?signin=1`. All referenced CSS/JS in the app shell exist, so the browser loads without missing-file errors, and the auth/merge/session-restore paths no-op cleanly when `electronAPI` is absent. `npm test` is green at 61/0.

### Web-mode gate and Electron isolation

Detection is the absence of `window.electronAPI`. The inline head script sits after `<title>` and before every stylesheet link, adding `web-mode` to `document.documentElement` so `css/web.css` applies on first paint. That stylesheet is linked last, after `css/auth.css`, and every rule is scoped under `html.web-mode`, so it wins by source order without `!important`. The two task commits (`de5dac4`, `0b6b221`) changed only `index.html`, `css/web.css`, `web/index.html`, `web/marketing.css`, `web/marketing.js`, and the FEAT JSON — the protected files (`main.js`, `preload.js`, `*.ps1`, `ios/`, `dist/`, `mini.html`) were untouched by this work (confirmed via `git diff 3e20f5a HEAD --name-only`). Toggling the class off restores the narrow Electron look, which is the proof that the change is fully browser-scoped.

### Full-width layout and responsiveness

`html.web-mode .page` becomes `max-width:1200px; margin:0 auto; width:100%`, and the nav is padded with `max(0.8rem, calc((100vw - 1200px)/2))` so it aligns to the same band (confirmed). `#page-calendar` is overridden to `max-width:none` so it stays full-width. Desktop ≥1025px gives `.timer-layout` a two-column grid and `.timeblock-layout` a three-column grid; tablet 601–1024px drops the scheduler to two columns with the time-block grid spanning both. Mobile ≤600px stacks the nav, wraps `.timer-controls`, makes scheduler input groups full-width, allows `overflow-x:auto` on `.cw-scroll`/`.cw-header-row`, tightens the heatmap gap, and caps every modal (`.cw-modal-content`, `.auth-content`, `.reflection-content`, `.timeline-content`, assign/plan-day) at `max-width:100%` with lighter padding — so the auth, reflection, and calendar-event modals all fit a 375px viewport.

### Sign-in path

`supabase-config.js` carries a real `SUPABASE_URL` and anon key and `isConfigured()` returns true, so `renderModal` runs the live email-OTP flow (email step → 6-digit code step → signed-in view) rather than the "not configured" placeholder. `auth-ui.js` wires `#nav-account` to `openModal` and sets `window.openAuthModal = openModal`. The browser deep-link in index.html's bottom inline block returns early under `window.electronAPI`, reads `signin===1` or `#signin`, and calls `window.openAuthModal()` only when the flag is set — so `/index.html?signin=1` opens the modal and plain `/index.html` does not (confirmed by reading the guard). `restoreSessionOnLaunch` returns immediately without `electronAPI`, so no browser console error from the missing session bridge.

### Marketing page

`web/index.html` links `../css/style.css` directly for the `:root` tokens plus `marketing.css`, so there is no duplicated or invented palette — the brand color, accent, border, radius, and font all resolve to the app's values. Every visual (hero timer dial, feature cards, history heatmap, step numbers) is inline SVG or CSS; a grep for `<img` returns no matches, so there are no broken-image placeholders. CTAs use the app's `.btn`/`.btn-primary`/`.btn-ghost` classes with `:focus-visible` outlines added in `marketing.css`, and point to `../index.html` (launch), `https://github.com/sonellmalik/Intention/releases/latest` (download), and `../index.html?signin=1` (sign-in). `marketing.js` is a tiny progressive-enhancement hamburger toggle that closes on link-click and Escape and maintains `aria-expanded`.

### Verification evidence

`npm test` reports 61 passing / 0 failing (confirmed by running it). A static server returned 200 for `/index.html`, `/css/web.css`, `/web/`, `/web/marketing.css`, `/web/marketing.js`, and `/css/style.css`. Every CSS and JS file referenced by the app shell exists on disk, so there are no 404s driving console errors.
